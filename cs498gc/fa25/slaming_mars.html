Part 2 (Part B): SLAM on Mars, Gazebo view

The Husky + UR3 drives away from the camera and loops among the rocks of the Mars world (mars.sdf), video at 10x speed. The drive is a scripted loop meant to revisit earlier ground: six legs of 40 s forward at 0.35 m/s, each followed by a 10.5 s turn at 0.5 rad/s (about 5.25 rad, roughly 300 degrees, per commanded turn, so the path is not a square; about 5 min in total). The SLAM log of this run records no loop closure. EKF sensor fusion and SLAM Toolbox (online async) ran alongside; Nav2 was launched but did not activate in this run.

Commands used in these runs

These are the launch commands from the TA run scripts, with long lines wrapped and absolute paths shortened to the TA workspace ($HOME/assignment4_ws) on the DGX Spark; before the Part 2 launch, the Part 2 script adds the workspace models/ and worlds/ folders to GZ_SIM_RESOURCE_PATH.

# Part 1 (Part A): Husky + UR3 + gripper simulation, headless server ros2 launch husky_ur3_gazebo simulation.launch.py world:=empty.sdf \ rviz:=false headless:=true # Part 2 (Part B): Mars world, SLAM Toolbox, Nav2 (launched, but it did not activate in this run), map saver ros2 launch husky_ur3_gazebo simulation.launch.py world:=mars.sdf \ rviz:=false headless:=true ros2 launch slam_toolbox online_async_launch.py use_sim_time:=true \ slam_params_file:=$HOME/assignment4_ws/src/husky_ur3_manipulation/config/slam_params.yaml ros2 launch nav2_bringup navigation_launch.py use_sim_time:=true ros2 run nav2_map_server map_saver_cli \ -f ~/assignment4_ws/deliverables_20260714/part2/part2_slam_map_20260714_053801 \ --ros-args -p save_map_timeout:=10.0 -p use_sim_time:=true
Where the ROS 2 packages come from: husky_ur3_gazebo, husky_ur3_description, the mars.sdf world and the custom ekf_sensor_fusion and path_planner nodes (package husky_ur3_manipulation) come from the TA's ROS 2 Jazzy workspaces, a port of the course simulator. The public course fork, kulbir-ahluwalia/husky_ur3_simulator, is the ROS 1 Noetic version (branch noetic-devel): its packages are catkin packages with ROS 1 launch files, so the ROS 2 commands above do not run from it.

🌌 Mission Overview

Assignment 4 (Fall 2025) combined mobile navigation with manipulation in Mars-themed Gazebo worlds.

🤖 Robot Configuration

  • Base: Clearpath Husky (4-wheel differential drive)
  • Arm: UR3 6-DOF manipulator
  • Gripper: Robotis gripper for sample collection
  • Sensors:
    • RGB-D camera for visual SLAM
    • LiDAR for terrain mapping
    • IMU for orientation in low gravity
  • SLAM: RTAB-Map or custom implementation

🔴 Mars Environment Features

  • Mars gravity: about 38% of Earth's (3.71 m/s² in the repo world)
  • Obstacles: rock-like blocks for navigation and SLAM
Fall 2025 handout text

The Fall 2025 handout also listed dust storms, uneven terrain and NASA rover data. None of these are in the linked worlds.

🛠️ Complete Setup & Installation

Prerequisites
  • Ubuntu 22.04 + ROS 2 Humble + Gazebo Fortress, or Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic (TA reference implementation)
  • NVIDIA GPU recommended (GTX 1060 or better)
  • 16GB RAM minimum

Step 1: Environment Setup

Configure ROS2 Jazzy/Humble with Gazebo Harmonic

source /opt/ros/jazzy/setup.bash mkdir -p ~/assignment4_ws/src && cd ~/assignment4_ws

Step 2: Clone Repositories

Get Husky UR3 simulator and Mars worlds

cd ~/assignment4_ws/src git clone https://github.com/kulbir-ahluwalia/husky_ur3_simulator.git # optional, not recommended in rubric v11 (missing meshes; fork of itsyashk/ros2-dual-robot-slam-explorer) git clone https://github.com/kulbir-ahluwalia/ros2-dual-robot-slam-explorer.git

husky_ur3_simulator is the ROS 1 Noetic reference (branch noetic-devel): it holds catkin packages with ROS 1 launch files, not ROS 2 packages. The ROS 2 Jazzy setup used for the TA runs, including the launch commands in Step 5, is described in the TA reference runs section.

Step 3: Install Dependencies

Install required ROS2 packages

cd ~/assignment4_ws sudo rosdep init 2>/dev/null || true rosdep update rosdep install --from-paths src --ignore-src -r -y pip3 install transforms3d

Step 4: Build Workspace

Compile all packages

colcon build source install/setup.bash

Step 5: Launch Mars Environment

Start the complete simulation

TA reference setup (not public)

husky_ur3_gazebo and mars.sdf come from the TA's ROS 2 Jazzy workspace, which is not public; the public husky_ur3_simulator is the ROS 1 Noetic version.

🎯 Pro Tips for Success
  • Start with flat Mars terrain before attempting craters
  • Use higher loop closure thresholds for dusty conditions
  • Implement sensor fusion early to handle wheel slip
  • Test in Earth gravity first, then switch to Mars
  • Save intermediate maps in case of crashes

🚨 Troubleshooting Guide

Problem: The robot doesn't respond to velocity commands
Solution: Add command_interface: "velocity" to your controllers.yaml file
base_controller: ros__parameters: command_interface: "velocity" # Add this line!

Problem: Gazebo crashes with OpenGL errors
Solution: Set software rendering mode
export LIBGL_ALWAYS_SOFTWARE=1 export MESA_GL_VERSION_OVERRIDE=3.3 ros2 launch husky_ur3_gazebo simulation.launch.py

Problem: Reduced traction on sandy Mars surface
Solution: Adjust wheel odometry covariance and use IMU fusion
Fall 2025 handout text (not a runnable command)
# Increase odometry uncertainty ros2 param set /husky_controller odom_covariance_xy 0.1 ros2 param set /ekf_filter imu_weight 0.8

Problem: UR3 arm overshoots in 38% gravity
Solution: Adjust PID gains for Mars gravity
Fall 2025 handout text (not a runnable command)
# Mars gravity compensation ros2 param set /ur3_controller gravity_compensation 3.71 ros2 param set /ur3_controller pid_p 0.6

Problem: Feature detection difficult in monochrome Mars environment
Solution: Tune visual feature detectors for Mars. We did not verify whether RTAB-Map picks up Vis/* changes made at runtime with ros2 param set, so the safe route is to pass them as launch arguments and restart the node:
# Pass RTAB-Map Vis/* parameters at launch (args is the rtabmap_launch argument for RTAB-Map parameters): # fewer inliers needed (default 20), GFTT/BRIEF features (type 6), up to 2000 features (default 1000). # Append your camera remaps (rgb_topic:=, depth_topic:=, camera_info_topic:=) and use_sim_time:=true, # and restart the node after any change. ros2 launch rtabmap_launch rtabmap.launch.py args:="--Vis/MinInliers 10 --Vis/FeatureType 6 --Vis/MaxFeatures 2000"

Problem: TF transform lookup fails with timeout
Solution: Increase timeout in launch files
# In your launch file, increase timeout transform_timeout = 5.0 # Increase from default 1.0
